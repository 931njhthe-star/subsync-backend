# 시스템 아키텍처 및 개발/배포 계획

## 1. 프로젝트 구조

본 프로젝트는 다음 3개 영역으로 분리한다.

### A. Chrome Extension — 사용자 클라이언트

사용자가 직접 설치하고 사용하는 프론트엔드이다.

기술:
- Chrome Extension Manifest V3
- HTML
- CSS
- JavaScript

예상 구조:

extension/
├── manifest.json
├── popup.html
├── popup.js
├── content.js
├── background.js
└── 기타 UI/리소스

역할:
- 사용자 UI 제공
- 웹페이지와 상호작용
- 사용자 입력 처리
- FastAPI Backend에 HTTP/HTTPS API 요청
- 서버 응답을 화면에 표시

개발 중에는 Chrome Web Store를 사용하지 않는다.

Chrome:
설정 → 확장 프로그램 → 개발자 모드 →
"압축해제된 확장 프로그램 로드"

방식으로 로컬 extension/ 디렉터리를 직접 로드한다.

## 2. FastAPI Backend — 서버

개발 환경:

개발자 PC
└── Python venv
    └── FastAPI
        ├── API Endpoint
        ├── 인증/인가
        ├── 비즈니스 로직
        ├── 외부 API/AI 호출
        ├── RDS 접근
        └── ElastiCache 접근

개발 초기 API 주소:

http://localhost:8000

Chrome Extension에서 localhost의 FastAPI API를 호출하여
클라이언트와 서버를 함께 개발/테스트한다.

## 3. 데이터 계층 — AWS

### RDS
- PostgreSQL 또는 MySQL
- 영구적으로 보존해야 하는 데이터 저장

예:
- 사용자 정보
- 서비스 데이터
- 학습 기록
- 결제/구독 관련 데이터

### ElastiCache
- Redis 또는 Valkey
- 빠른 접근이 필요한 임시 데이터 및 캐시 저장

예:
- 캐시
- 세션
- 임시 상태
- 반복 API 요청 결과

## 4. 개발 단계의 전체 구조

Chrome Extension
        │
        │ HTTP
        ▼
localhost:8000
FastAPI (venv)
        │
        ├──── AWS RDS
        │
        └──── AWS ElastiCache

## 5. 운영 서버 배포

기능 개발이 완료되면 FastAPI 서버를 Docker 컨테이너로 만든다.

FastAPI
   ↓
Docker Image
   ↓
AWS ECR
   ↓
AWS ECS
   ↓
AWS Fargate
   ↓
FastAPI 운영 서버

역할:

- Docker: FastAPI 실행환경 패키징
- ECR: Docker 이미지 저장
- ECS: 컨테이너 관리
- Fargate: 서버를 직접 관리하지 않고 컨테이너 실행

## 6. 운영 단계의 전체 구조

사용자
   ↓
Chrome Extension
   │
   │ HTTPS API
   ▼
AWS
└── ECS + Fargate
    └── FastAPI Container
         │
         ├── RDS
         │   └── PostgreSQL/MySQL
         │
         └── ElastiCache
             └── Redis/Valkey

## 7. 개발환경과 운영환경 구분

개발환경:
Chrome Extension
→ localhost:8000
→ venv 기반 FastAPI

운영환경:
Chrome Extension
→ HTTPS 운영 API 주소
→ Docker 기반 FastAPI
→ ECS/Fargate

환경에 따라 API 주소와 DB 설정 등은 환경변수로 분리한다.

비밀번호, DB 접속정보, API Key 등의 Secret은
Chrome Extension 코드에 포함하지 않는다.
Secret은 반드시 서버 측에서 관리한다.

## 8. Chrome Extension 배포 전략

### 1단계 — 현재
개발자 모드의 "압축해제된 확장 프로그램 로드" 사용

### 2단계 — 내부 테스트
완성된 extension 디렉터리를 테스트 환경에서 사용

### 3단계 — 정식 출시
Chrome Web Store 등록
→ Google 심사
→ 승인
→ 일반 사용자 설치
